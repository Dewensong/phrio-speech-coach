# Phrio 编辑校样式体验改造计划

## 目标

在不改变训练状态机、数据图、IPC、隐私与云端同意边界的前提下，把 Phrio
从“能力完整但技术信息同时外露的训练工作台”改造成“安静、清晰、有辨识度的
表达排练桌”。

视觉母题固定为：

> 编辑校样 × 表达排练 × 纸墨套印

新版继续使用现有 Phrio 标志中的连续深色 `P`、海绿色复讲副线与单一朱红焦点。
产品内不使用 AI 玻璃、柔光、霓虹、装饰波形或悬浮水晶球。

## 不可回归边界

- 不修改 Renderer → preload → IPC Controller → Service → Repository 单向依赖。
- 不修改 Session / Attempt / Snapshot / correction / report / focus / Drill /
  comparison 的身份和冻结规则。
- 不把 partial 写入历史，不把短提示冒充诊断，不产生总分或人格判断。
- 不改变本地模型校验、真实麦克风、停止收束、同录音重转和失败恢复行为。
- 不扩大 OpenAI provider、用途、payload 或同意范围；音频和 partial 继续禁止出站。
- 不改变本地数据删除、录音保留、诊断日志和分享卡隐私规则。
- 保留 system/light/dark、8 组约束配色、90%–125% 缩放、键盘焦点和 reduced motion。
- 受控 Fixture、自动化和真实设备证据继续分开陈述，不能互相替代。

## 功能保全矩阵

| 现有能力 | 新版第一层 | 新版第二层或异常层 | 验收证明 |
| --- | --- | --- | --- |
| 首次进入与处理边界 | 简洁本地优先说明、30 秒受控 Demo | 完整隐私说明 | product tour；Fixture 零麦克风/零记录/零网络 |
| 自由练习 | 首页主输入与唯一主 CTA | 听众、目标折叠为“练习条件” | 组件交互；真实 Session 创建 |
| 模式、题库、收藏 | 首页三模式与 3 条推荐；题库集合入口 | 全量搜索、收藏和社区 Pack 留在题库 | 组件测试；真实设置持久化 |
| 练习准备 | 一张“排练单”显示任务、听众、目标、时长 | 冻结约束、内容版本、本地数据说明 | Session task snapshot 集成测试 |
| 模型与麦克风 | 开始前只显示是否可开始 | 安装/暂停/恢复、设备、输入健康在异常态或详情 | installer、device、真实麦克风证据 |
| partial / final | 当前句与已落定原句 | 完整计数、来源与时序进入采集详情 | reducer/ASR 测试；真实设备 |
| 实时证据 | 专注模式显示当前一条建议 | 证据模式保留完整逐句账本、O 编号和全屏 | visual 账本断言；Fixture |
| 停止与恢复 | 停止并整理为唯一主动作 | no-speech、短录音、重录、重转、保存重试按事实上浮 | 录音组合测试；真实停止收束 |
| 逐字稿纠正 | 可编辑讲话稿与固定音频条 | 原始 final、版本和纠正历史 | correction/reference tests |
| 诊断结果 | 结论 → 证据 → 唯一焦点 → 下一步 | 版本、完整逐字稿、lifecycle 和 payload 审计折叠 | diagnosis hierarchy tests |
| 诊断后分支 | 结束、自由复讲、聚焦 Drill 三条显式路径 | exact report/focus/Drill identity 不变 | Deep Lane 集成与对抗测试 |
| Drill | 单动作、示例、计时、自检 | 冻结 comparison dimension | Drill completion tests |
| 复讲与比较 | 初讲/复讲双页，只比较冻结口径 | 音频、完整证据和 insufficient evidence | comparison graph tests |
| 记录管理 | 记录列表与结果摘要 | 重命名、置顶、删除、恢复、完整证据双视图 | schema v8 与 product tour |
| 分享 | 完成结果旁的本地导出 | 16:10 / 1:1 / 9:16、证据 opt-in、纯净展示 | share privacy/layout tests |
| 外观与无障碍 | 使用体验分组 | 主题、配色、缩放、reduced motion 全量保留 | token/contrast/visual matrix |
| AI 与隐私 | 独立用途状态与明确开关 | Key、exact payload、撤回、清除和审计 | cloud consent/adversarial tests |
| 诊断支持 | 状态摘要 | 打开目录、导出、清除、容量与丢弃计数 | diagnostics integration tests |

“移到第二层”只表示降低正常状态的视觉权重。任何导致数据不完整、无法继续或
需要用户决策的异常，都必须自动回到当前页面第一层，且保留原恢复动作。

## 信息架构

### 全局导航

- 一级对象：新练习、练习记录、收藏题目、练习设置。
- 外观、常规与隐私继续位于底部，并保持独立设置上下文。
- 模式仍是本轮任务条件，不提升为全局对象。
- 最近练习仍直接打开冻结记录，紧凑侧栏不复制第二套数据或操作逻辑。

### 首页与准备

- 首页先回答“现在想练什么”，自由练习为视觉主角。
- 听众与目标保留，但折叠为可选练习条件；默认值与创建语义不变。
- 受控 Demo 是低压力入口，永久标注 Fixture 边界。
- 模板区域只展示 3 条推荐，完整题目、搜索、模式和收藏留在题库。
- 准备页是一张可编辑排练单，开始动作只有一个。

### 实时练习

- 默认“专注模式”：任务、计时、输入状态、当前句、final 原句、当前建议和停止。
- 可切换“证据模式”：恢复现有完整账本与证据全屏。
- 三通道技术状态压缩成一个健康摘要；设备、ASR、网络和 final 统计进入详情。
- 错误、降级和恢复仍按当前事实自动上浮，不因视觉简化而隐藏。

### Deep、记录与传播

- 逐字稿改为可编辑讲话稿。
- 诊断继续使用已批准的结果层级，只收起审计信息。
- Drill 保持一个动作；比较保持一个冻结标准，不引入总分。
- 记录默认先展示结果，再提供冻结实时证据。
- 分享从记录的次级工具提升为完成后的自然终点，但仍只在本机生成。

## 视觉系统

- 基础：暖纸、深墨、海绿套印、单一朱红校样焦点。
- 布局：减少同权卡片，使用留白、细线、页码、栏目标记和边注建立层级。
- 字体：正文保留系统无衬线；大标题、题目和关键原句使用系统宋体回退；
  等宽字体只用于版本、时间、证据编号和技术状态。
- 尺寸：正文 14–16px，辅助信息原则上不低于 11–12px。
- 圆角：主要纸张 2–6px；按钮和状态不再全部使用同一大圆角。
- 动效：只使用 120–200ms 的排版出现、划线和轻微套印对齐；reduced motion
  下立即完成，不删除状态。
- 深色：表达为“炭黑纸上的浅墨”，不转换成发光霓虹界面。

## 分阶段实现

1. **基线冻结**：功能矩阵、截图、测试和证据口径。
2. **视觉基础**：Token、应用外壳、导航、标题、按钮和纸张层级。
3. **首次成功**：首页、题库入口、准备页和受控 Demo。
4. **核心工作区**：实时页专注/证据分层、停止收束与异常上浮。
5. **训练闭环**：逐字稿、诊断、Drill、复讲和比较。
6. **长期使用**：记录、详情、设置、分享和传播素材。
7. **完整验收**：自动化、受控 Fixture、真实设备与诚实边界。

每一阶段独立可回退。迁移期间允许开发/QA 使用纯展示层开关对照新旧布局，
但不建立两套业务逻辑。旧展示组件只有在对应功能映射和门禁通过后才移除。

## 最终门禁

### 自动化证据

- `pnpm verify`
- `pnpm verify:electron-visual`
- `pnpm verify:electron-product-tour`
- 分享卡、受控 Demo、主题对比度、键盘焦点与横向 overflow 专项断言

### 受控 Fixture 证据

- 1440×960、1024×960，100% 与 125%
- system/light/dark、代表性浅/深配色、reduced motion
- 自由练习、诊断三分支、Drill、自由复讲、聚焦复讲、可选比较
- 记录管理、诊断/冻结证据双视图和三种分享比例
- console 0 error / 0 warning，外部 HTTP(S) 请求 0

### 真实设备证据

- 模型安装/重启 ready
- 真实麦克风、partial/final、停止尾句和快照持久化
- 设备切换、中断、恢复和长时间稳定性
- 本地模型中文表达质量与目标 Mac 性能
- 用户独立授权后的真实 OpenAI 用途；没有授权时不调用
- Developer ID、公证、Gatekeeper 和升级后的 TCC 连续性只在获得凭据后验证

## 发布边界

完成视觉改造不自动改变发布级别。Developer ID / 公证、目标 Mac 性能、真实设备
中断矩阵和本地模型质量未关闭前，建议仍是继续 Internal Alpha。任何 remote、
main、合并、Release 或公开分发继续需要 Dewens 单独授权。
